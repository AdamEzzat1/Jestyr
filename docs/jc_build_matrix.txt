# jc_build_matrix.txt -- can the SELF-HOSTED compiler build every multi-module program in
# the corpus? One line per `examples/std/*.jtr` that declares `fn main()` and has at least
# one `import "..."`, sorted; `BUILD_OK` or `FAIL`.
#
# WHY THIS FILE EXISTS
#
# `jc build` is the only path that exercises the port's own module loader, and no gate
# covered it. `selfhost_fixpoint_subset` `continue`s on any file containing `import "` by
# construction, and `jestyr_cgen_matches_reference` feeds every file to both backends with
# imports UNRESOLVED -- so a program could be byte-identity verified AND unbuildable, which
# is exactly what nine of them were. The 2026-08-20 census audit recorded the hole and the
# gate it owed; this is that gate.
#
# IT IS AN EXPECTATIONS FILE, NOT A GREEN/RED GATE, AND IT FAILS IN BOTH DIRECTIONS.
# Every entry is BUILD_OK today, which is NOT a reason to turn it into a pass/fail gate: a
# regression has to move a line here deliberately, and the two-directional half is not
# theoretical. The loader fix that took this matrix from 43 BUILD_OK to 49 ALSO moved
# `test_demo` from BUILD_OK to FAIL on its first attempt, because the new exclusion caught
# `const NAME: T` along with struct fields. Nothing else in the tree would have noticed.
#
# **BUILD_OK IS NOT CORRECT, AND THIS FILE CANNOT TELL YOU THAT IT IS.**
#
# A verdict here means `jc` produced a binary. It does not mean the binary behaves. That
# distinction is not hypothetical: while the last four failures were being closed,
# `combinators` reached BUILD_OK while still printing 0 for every `Option`/`Result`
# combinator, because the port emitted `bool jestyr_opt_is_some__i32(...) { }` -- an EMPTY
# BODY -- and gcc accepts a non-void function that falls off its end with a warning.
# Regenerating the matrix at that moment would have recorded a silent miscompile as a
# success.
#
# So `jc_built_generics_run_the_same_as_the_reference` (in `src/proptests.rs`) RUNS the
# jc-built binary against the reference's for the four programs whose monomorphized generics
# were the fix, plus `log_demo`/`str_demo` as controls, and compares the bytes. Extending
# that comparison to all 57 is the obvious follow-up; it doubles the runtime, and those six
# are where the evidence is.
#
# THE FOUR THAT USED TO FAIL WERE SIX GAPS, NOT ONE MECHANISM. This file previously recorded
# them as "one def-emission gap" plus an inference gap. Measured, both halves of that were
# wrong: the port's `collect_fn_types` was missing its THIRD pass (generic FUNCTION instances'
# fn-pointer params), `push_su_mangle` had no type-application arm, `emit_su_tyid` had no
# Slice arm, five body emitters reached for the unsubstituted renderer, the two primitive
# tables stopped at code 15 -- and `try_read` was a MANGLE gap, not an inference one (typeck
# agrees with the reference on that file; only the emission was wrong). See
# `docs/session-notes/jestyr-port-monomorphization-handoff.md`.
#
