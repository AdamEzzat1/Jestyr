# jc_build_matrix.txt -- can the SELF-HOSTED compiler build every multi-module program in
# the corpus? One line per `examples/std/*.jtr` that declares `fn main()` and has at least
# one `import "..."`, sorted; `BUILD_OK` or `FAIL`.
#
# WHY THIS FILE EXISTS
#
# `jc build` is the only path that exercises the port's own module loader, and no gate
# covered it. `selfhost_fixpoint_subset` `continue`s on any file containing `import "` by
# construction, and `jestyr_cgen_matches_reference` feeds every file to both backends with
# imports UNRESOLVED -- so a program could be byte-identity verified AND unbuildable, which
# is exactly what nine of them were. The 2026-08-20 census audit recorded the hole and the
# gate it owed; this is that gate.
#
# IT IS AN EXPECTATIONS FILE, NOT A GREEN/RED GATE, AND IT FAILS IN BOTH DIRECTIONS.
# Four entries are FAIL today, and pretending otherwise would mean either a permanently red
# suite or a silently shrinking one. A fix has to move a line here deliberately.
#
# The two-directional half is not theoretical: the loader fix that took this matrix from 43
# BUILD_OK to 49 ALSO moved `test_demo` from BUILD_OK to FAIL on its first attempt, because
# the new exclusion caught `const NAME: T` along with struct fields. Nothing else in the
# tree would have noticed.
#
# THE FOUR REMAINING FAILURES ARE ONE MECHANISM, now isolated (the census recorded it as
# "mechanism not isolated"): the port emits a generic typedef's NAME into a prototype
# without emitting the typedef itself.
#
#   combinators  JestyrFn_fn_di32_ret_?          fn-pointer typedef, return mangled empty
#   mutex        JestyrFn_fn_dptr_i64_ret_unit   fn-pointer typedef never defined
#   slice_algos  JestyrFn_fn_ri32_ri32_ret_bool  same, with a `read` parameter
#   try_read     JestyrResult_                   an UN-ANNOTATED `let ok = fs.try_read_text(p)`
#                                                infers nothing, so the ok type mangles empty
#
# The first three are one def-emission gap: a fn-pointer instance reached only through the
# flattened program is named but never emitted. `try_read` is the other half -- the port's
# INFERENCE, not its emission. Annotating that `let` would work around it, and that is
# deliberately NOT done, because the workaround would hide the gap this file records.
#
